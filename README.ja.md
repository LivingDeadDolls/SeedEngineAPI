# Seed Engine API

[English](README.md) | 日本語

ワールドで何が生成されるかを、シードからゲーム自身のコードで計算し、ほかの MOD に渡す Fabric 向けの前提 MOD です。
単体では `/setseed` のコマンドを足すだけです。これを必要とする MOD と一緒に、その MOD と同じ側（クライアント・サーバー・その両方）に入れてください。

## 機能

シード・ワールドの種類（デフォルト・大きなバイオーム・アンプリファイドなど）・ディメンションか、サーバーのワールドを指定すると、次のものを計算します。

- 構造物: それぞれの構造物が始まる場所と、全体を囲む箱。バイオームや地形の判定も含めて、ワールドの生成と同じように決めます。部屋や建物ごとの箱（村の家、要塞の部屋）も、その種類と置くテンプレートと一緒に出します。エンドシティでは、どれが船かもわかります。
- 構造物のブロックとスポナー: 構造物が置くブロックと、スポナーとそのモブ（廃坑、要塞、ネザー要塞、試練の間）。ワールドがチャンクを生成した順番で変わるもの（廃坑の通路がクモのスポナーを置く場所など）は、確かでないブロックとスポナーと、それぞれありうるものを出します。
- ダンジョン: ある範囲のダンジョンとそのモブ。地形と洞窟を、ワールドの生成と同じ手順で作ってから決めます。
- 地形の高さとバイオーム: どの場所でも出せます。あるバイオームのいちばん近い場所（`/locate biome` と同じ探し方）、範囲のバイオームを決まった間隔で並べたもの、そのディメンションで生成されうるバイオームの一覧も出せます。
- 構造物が独自のモブを湧かせる範囲: 構造物（前哨基地・海底神殿・魔女の小屋・ネザー要塞）ごとに、バイオームのモブの代わりにその構造物のモブが湧く箱と、湧くモブ。

シードだけから、村人の取引も計算します。取引の組（司書のレベル 1 など）ごとに、ワールドでその職に就いた（またはそのレベルに上がった）1 人目の村人の取引、2 人目の取引、と順に出します。ワールドがいま何人目まで進んでいるかは、シードだけでは分かりません。製図家の探検家の地図は、ワールドを探すので計算しません。

シードで指定したときは、ゲームに入っているバニラのデータを使うので、ワールドの生成と取引がバニラのままのサーバーなら合います。サーバーのワールドで指定したときは、そのサーバーのデータパックも入ります。

Spigot や Paper のサーバーは、構造物や地物の一部を、ワールドの seed とは別の seed で置くことがあります（`spigot.yml` の `seed-village` など、Paper の `feature-seeds`）。この seed はクライアントには送られません。サーバーの設定からその値が分かれば、それを渡すことで、そのサーバーと同じ答えを出せます。

### 今いるワールドのシード

クライアントでは、今いるワールドのシードを持っておき、それを使う MOD に渡します。

- シングルプレイと、自分が LAN に公開したワールドでは、入るとすぐにシードが分かります。
- サーバーでは `/setseed <シード>` でシードを入れるか、サーバーが許していればバニラの `/seed` を実行してください。シードは数字か文字で、文字はワールド作成の画面と同じように読みます。`/setseed clear` は入れたシードを消し、`/setseed` だけなら、使っているシードとその出どころを出します。
- 入れたシードと `/seed` の結果はサーバーごとに覚えておき、次にそのサーバーに入ったときにも使います。入れたシードがあれば、`/seed` の結果より先に使います。
- 今いるワールドの種類（デフォルト・大きなバイオーム・アンプリファイド）も見分けます。シングルプレイではワールドそのものから読み、サーバーでは、シードが分かったあとに、まわりの地形から見分けます（サーバーはワールドの種類をクライアントに送らないため）。シードとワールドの種類が届いた地形と合わないこと（シードの入れ間違いや、生成を変えているサーバー）にも気づき、それを使う MOD が知らせられるようにします。

## MOD の作者の方へ

`seedengine.api.SeedEngineApi` に問い合わせて使います。どの問い合わせをどのスレッドから呼べるか、どれが重いかは Javadoc に書いてあります。`currentSeed()` で、クライアントが今いるワールドのシード（分かっていれば）を読めます。シードが変わると、`addSeedListener` に渡した処理が呼ばれます。ワールドの種類も同じように `currentWorldType()` で読めて、変わると `addWorldTypeListener` に渡した処理が呼ばれます。シードとワールドの種類が届いた地形と合っているかは、`currentWorldCheck()` で分かります。
各リリースに付けている jar を使ってビルドし、`fabric.mod.json` の `depends` に `seedengine` を書いてください。Loom の `include` で、あなたの MOD の jar の中に入れて配ることもできます。そうすれば、プレイヤーはあなたの MOD を 1 つ入れるだけで済みます。複数の MOD が入れていても、Fabric Loader が読むのはいちばん新しい版だけです。一度出したメソッドは引数も意味も変えないので、古い版に合わせて作った MOD も新しい版で動きます。

## 必要なもの

- [Fabric Loader](https://fabricmc.net/use/)
- [Fabric API](https://modrinth.com/mod/fabric-api)
